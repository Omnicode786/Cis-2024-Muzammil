1. Stacks and Expressions (Lectures 13–14)

1.1 What a Stack Is

A stack is a simple data structure where you add and remove items only from the top. You can imagine a stack of plates: you put a plate on the top, and you also take from the top.

Basic operations:

  • push(x) – put x on the top of the stack
  • pop() – remove and return the top item
  • peek() – look at the top item without removing it
  • isEmpty() – check if the stack has no items

Rule: LIFO – Last In, First Out. The last item you pushed is the first one that will come out.

Stacks can be implemented using a Python list (top at the end of the list) or a linked list (top is the head node).

Time per operation (push, pop, peek): O(1). Space per item: O(1).

1.2 Expression Formats

We deal with three forms of arithmetic expressions:

  • Infix: operator is in the middle (e.g., A + B, 3 * (4 + 5)).
  • Prefix: operator comes before operands (e.g., + A B, * 3 + 4 5).
  • Postfix: operator comes after operands (e.g., A B +, 3 4 5 + *).

Humans like infix, but computers find prefix/postfix easier because they avoid parentheses and operator precedence rules.

1.3 Evaluating Postfix Expressions

Algorithm (using a stack):

  1. Read tokens from left to right.
  2. If the token is a number or variable → push it onto the stack.
  3. If the token is an operator (+, −, ×, ÷, etc.):
    • pop the top two values,
    • apply the operator (second popped is left operand, first popped is right operand),
    • push the result back onto the stack.
  4. At the end, the stack has one value: the answer.

Time Complexity: We process each token once, each stack operation is O(1), so total is O(n).

Space Complexity: We store operands on the stack, proportional to n → O(n).

1.4 Converting Infix to Postfix

We use an operator stack:

  1. If the token is an operand → send it directly to output.
  2. If the token is an operator:
    • while the stack top has an operator with higher or equal precedence, pop it and add to output,
    • then push the new operator.
  3. If the token is '(' → push it.
  4. If the token is ')' → pop from stack to output until '(' is found. Discard both parentheses.
  5. After processing all tokens → pop remaining operators to output.

Time Complexity: O(n)

Space Complexity: O(n)

2. Quicksort (Lectures 15–16)

2.1 Idea of Quicksort

Quicksort is a divide and conquer sorting algorithm:

  1. Pick a pivot element from the array.
  2. Rearrange elements so that:
    • all elements less than pivot are on the left,
    • all elements greater than pivot are on the right.
  3. Recursively apply the same process to the left and right parts.

No explicit “merge” step is required; concatenating left part + pivot + right part gives the sorted array.

2.2 Time Complexity

Let n = number of elements.

  • Best case: pivot splits the array into two equal halves each time.
    Recurrence: T(n) = 2T(n/2) + n → O(n log n).
  • Average case: pivots tend to be reasonably balanced → O(n log n).
  • Worst case: pivot is always smallest or largest (e.g., sorted input with bad pivot choice).
    Recurrence: T(n) = T(n − 1) + n → O(n²).

2.3 Space Complexity

Space depends on recursion depth (or size of manual stack):

  • Best/Average: height ≈ log n → O(log n) space.
  • Worst: height = n → O(n) space.

2.4 How to Improve Quicksort

  • Use a random pivot.
  • Use median-of-three pivot (first, middle, last).
  • Use tail recursion elimination where possible.
  • Use insertion sort for small subarrays.

3. Recursion (Lecture 17)

3.1 What Is Recursion?

A function is recursive if it calls itself. It must have:

  • a base case (when to stop),
  • a recursive case (smaller problem).

Each call adds an activation record to the run-time stack (local variables, return address, etc.). When the function returns, that record is removed.

3.2 Factorial Example

Recursive definition:

  • n! = n × (n − 1)! if n > 0
  • 0! = 1

Recursive function:

  • If n == 0 → return 1.
  • Else → return n * factorial(n − 1).

Time: O(n), Space: O(n)

3.3 Printing Numbers

printdec(n): prints n, n−1, ..., 1

printasc(n): prints 1, 2, ..., n

Both functions:

  • Call themselves n times → O(n) time.
  • Use recursion depth n → O(n) space.

3.4 Naive Fibonacci

Definition:

  • F(0) = 1, F(1) = 1
  • F(n) = F(n−1) + F(n−2) for n > 1

The naive recursive Fibonacci repeats the same work many times (overlapping subproblems).

  • Time: Θ(2ⁿ) (exponential)
  • Space: O(n) (height of recursion tree)

3.5 Efficient Fibonacci – goodfib

A better version returns a pair (F(n), F(n−1)). From (F(n−1), F(n−2)) you can compute: (F(n), F(n−1)) = (F(n−1)+F(n−2), F(n−1)).

Each level does constant work and makes one recursive call.

  • Time: O(n)
  • Space: O(n)

4. Binary Trees (Lectures 19–21)

4.1 Tree Terminology

A tree consists of nodes connected by edges. Key terms:

  • Root: top node.
  • Parent: node that has children.
  • Child: node below a parent.
  • Siblings: nodes with the same parent.
  • Leaf: node with no children.
  • Subtree: any node and all its descendants.
  • Path: sequence of connected nodes.
  • Height: number of levels from root to deepest leaf.
  • Depth of node: distance from root.
  • Size: total number of nodes.
  • Width: maximum nodes on any level.

4.2 Binary Trees and Height

A binary tree is a tree where each node has at most 2 children (left and right). If a tree has n nodes:

  • Minimum height: when perfectly balanced (perfect tree) → n = 2^h − 1 → h = log₂(n + 1).
  • Maximum height: when each node has one child (like a list) → h = n.

4.3 Special Binary Trees

  • Strictly Binary (Full) Tree: every interior node has exactly 2 children.
  • Perfect Binary Tree (PBT): strictly binary and all leaves at the same level; has 2^h − 1 nodes.
  • Almost Complete Binary Tree (ACBT): all levels are full except possibly the last, and the last level is filled from left to right with no gaps.

4.4 Binary Tree Implementation

Each node typically stores:

  • data – the value;
  • lc – left child pointer;
  • rc – right child pointer.

Operations like adding/removing children (e.g., addlc, addrc, dellc, delrc) are O(1) time and space.

4.5 Tree Functions and Complexity

Most tree functions visit each node exactly once:

  • height(): returns tree height.
  • nodecount(): counts all nodes.
  • leafcount(): counts all leaves.
  • isStrictlyBinary(): checks if each interior node has 2 children.
  • isPerfect(): checks if nodecount() == 2^height − 1.

Time Complexity: O(n) (each node visited once).

Space Complexity: O(h) (h = tree height, due to recursion depth).

4.6 Checking Almost Complete – isAlmostComplete()

An Almost Complete Binary Tree must obey strict rules about heights and how nodes are filled. isAlmostComplete uses:

  • height()
  • isPerfect()
  • and recursive checks on left/right subtrees.

It considers whether left and right subtrees are perfect or almost complete, and whether their heights differ by at most 1 in the correct pattern.

Because it repeatedly calls other O(n) functions and the height is O(log n) for ACBT:

  • Time Complexity: O(n log n)
  • Space Complexity: O(log n)

4.7 Tree Traversals

Depth-First Traversal (DFS):

  • Inorder (LNR): left → node → right
  • Preorder (NLR): node → left → right
  • Postorder (LRN): left → right → node

Each DFS traversal:

  • Time: O(n) – each node visited once.
  • Space: O(h) – recursion depth.

Breadth-First Traversal (BFS):

  • Uses a queue; visits nodes level by level, from left to right.
  • Time: O(n)
  • Space: O(n) (queue can hold nodes from a full level).

5. Heaps and Heapsort (Lectures 22–23)

5.1 What Is a Heap?

A heap is a special binary tree used for fast access to the largest (or smallest) element. For a max-heap:

  • The structure is an Almost Complete Binary Tree.
  • Heap property: each parent node is ≥ its children.

We store the heap in an array:

  • root at index 0,
  • left child of index i → index 2i + 1,
  • right child of index i → index 2i + 2,
  • parent of index j → index floor((j − 1) / 2).

5.2 Insert into Heap (Rise)

  1. Append new value at the end of the array (maintains complete tree shape).
  2. Rise or “bubble up”:
    • while the new value is greater than its parent, swap it with the parent.

Height of heap is about log n.

  • Time: O(log n)
  • Space: O(1) extra (in-place)

5.3 Delete from Heap (Sink)

To delete the maximum (root):

  1. Replace root with the last element in the array.
  2. Reduce heap size by 1.
  3. Sink or “bubble down”:
    • while this element is smaller than any of its children, swap it with the larger child.
  • Time: O(log n)
  • Space: O(1) extra

5.4 Building a Heap (as per slides)

If the heap is built by inserting each element and then rising:

  • Each insert: O(log n)
  • n inserts: O(n log n)

Space: O(n) for the array holding the elements.

5.5 Heapsort

Steps:

  1. Build a max-heap from the unsorted list.
  2. For i from 0 to n−2:
    • swap element at index 0 (largest) with element at index n−1−i,
    • reduce the considered heap size by 1,
    • sink the new root to restore heap property.

Time Complexity:

  • Build heap: O(n log n) (as done in slides).
  • n−1 delete-max operations, each O(log n): O(n log n).
  • Total: O(n log n)

Space Complexity:

  • In-place: uses the same array and a few temp variables.
  • Extra space: O(1).

6. Binary Search Trees (BSTs) – Lecture 23

6.1 Definition of BST

A Binary Search Tree (BST) is a binary tree where:

  • All values in the left subtree of a node are less than the node’s value.
  • All values in the right subtree are greater than the node’s value.

An inorder traversal of a BST produces values in ascending order.

6.2 Building a BST

Given a list of values:

  1. First value becomes the root.
  2. For each next value:
    • compare with current node,
    • if smaller → go to left child,
    • if larger → go to right child,
    • continue until a None position is found and insert there.

Time per insert: O(h), where h is the tree height.

6.3 BST Search

To search for a target:

  1. Start at root.
  2. If node is None → not found.
  3. If target == node.data → found.
  4. If target < node.data → move to left child.
  5. Else → move to right child.
  6. Repeat until found or None.
  • Time: O(h)
  • Space: O(h) if recursive; O(1) if purely iterative.

Where h is the height of the BST.

  • Balanced BST: h ≈ log n → operations O(log n).
  • Skewed BST (e.g., sorted data): h = n → operations O(n).

6.4 BST Deletion

Deleting a node (the “victim”) has three main cases:

  1. Victim is a leaf: simply remove it by setting the parent’s pointer to None.
  2. Victim has one child: link the parent directly to the victim’s child.
  3. Victim has two children:
    • find the successor (smallest value in the right subtree),
    • copy successor’s value into the victim node,
    • delete the successor node (which will be in case 1 or 2).

Time: O(h) (locating victim, possibly successor, and adjusting links).

Space: O(h) if recursive; O(1) if fully iterative.

    • Insert/search/delete: O(h) time, O(h) space (recursive)
